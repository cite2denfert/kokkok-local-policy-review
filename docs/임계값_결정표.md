# 임계값 결정표 (근거 파일 real-002 이후)

임계값은 규칙이 질문을 띄우는 지점이다. 통계 검정의 유의수준이 아니라 운영 기준이다. 아래 값은 BC카드 제공 자료(2026-01~06, 255개 시군구)로 세 가지를 점검해 정했다. 시군구별 값은 없고 전국 분포와 집계만 실었다. 값은 `config/rules_thresholds.json`에서 관리하고, 숫자는 `src/11_threshold_decision.py`로 다시 계산한다.

- 재현성: 1~3월과 4~6월로 나눠 각각 뽑았을 때 같은 지역이 뽑히는가(겹침 정도, 0~1). 0.8 안팎 이상이면 안정적으로 본다.
- 발동 빈도: 규칙 하나가 전체 시군구의 20~25%를 넘게 걸리지 않는가.
- 절대 수준: 상대 순위만이 아니라 평소 변동보다 실제로 큰 값인가.

## real-001 → real-002에서 바뀐 것

R04만 바뀌었다. 이전(real-001)은 하위 20%가 1.25, 나머지가 1.10이었다. 규모 구간별 흔들림을 재 보니 하위 10%(0.127)와 10~30%(0.06~0.07)의 차이가 커서 두 구간을 따로 세웠다. 발동 지역은 32곳에서 30곳으로 줄었다. 5월에 22곳이 몰리는데, 전국 5월 흐름을 뺀 지수에서도 5월이 큰 지역이 많다는 뜻이며 6개월 자료로는 계절성으로 단정하지 않는다.

'같은 달 상위 20%'처럼 상대 순위로 정하면 매달 51곳이 자동으로 걸려 6개월 중 한 번이라도 걸리는 시군구가 74%가 된다. 그래서 절대 지수 기준으로 바꿨다.

## 아직 남은 것

- R08은 다른 규칙보다 재현성이 낮다(반기 겹침 0.75, 업종×연령 쌍에 따라 0.57~0.89).
- R11은 실제 입력 방문객 분포가 없어 시군구 인구로만 점검했다.
- 사용자 검증(담당자 반응)은 아직 하지 않았다. "질문이 너무 많다·적다"가 나오면 값을 조정하고 근거 파일을 다시 만든다.
- 인구감소지역 목록은 2021년 지정 기준이라 2026년 하반기 재지정 후 갱신이 필요하다.

## 값을 바꾸는 방법

`config/rules_thresholds.json`의 `thresholds`에서 값만 바꾸고 아래를 다시 실행한다. `dataset_versions`도 올린다.

```
python src/09_make_evidence.py real        # 비공개
python src/09_make_evidence.py synthetic
python src/10_verify_evidence.py           # 기대 집계값이 바뀌면 expected_real도 원인을 확인한 뒤 고친다
```
